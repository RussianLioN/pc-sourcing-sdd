# Plan — one writer, sequential integration
Python 3.13.3 / Pydantic 2.14.0 / SQLite stdlib, pytest 8.4.2,
Hypothesis 6.142.1, Ruff 0.14.0. Spec Kit 1.1.3 is coordinator only.
No runtime LLM, MCP, background service, UI, credentials or live adapters.
Dependencies are project-local and pinned; locks include transitive versions.

1. Coordinator freezes models, spec, decision table and golden cases.
2. Commit contract baseline; issue JSON task with SHA, revisions, ownership,
dependencies, fixed commands, output and stop condition.
3. Writer implements evaluation + pipeline in its worktree with unique DB,
temp, cache and logs. No shared mutable database, port or browser.
4. Run unit/contract/property tests, validate diff and protected Git blobs.
5. Integrate sequentially; run full tests on common snapshot.
6. Independent actual Codex read-only verifier uses same spec and commit.
7. Findings become narrow repair with added regression tests; max 2 rounds.
8. Recheck whole snapshot and independent verdict; preserve failed artifacts.
9. Accept offline only after required checks; live remains explicitly blocked.

Offer/Evidence/Evaluation versions are fixed at 1.0.0. SQLite stores validated
objects and rejects; persistence transaction is atomic and idempotent.
Coordinator scripts record commands, exits, versions, hashes and next step.
Golden baseline blobs live in coordinator main checkout, outside writer cwd;
integration compares all protected files to base Git objects, then rejects
unowned changes. Hash generated by writer alone cannot grant acceptance.
Read-only verifier is a distinct process with no code write authority.
Spec Kit shell is not a sandbox. Wrapper pins executable, rejects extra args,
sets workspace-write/read-only explicitly and applies wall-time termination.
Runner resume is only paused/failed, with project advisory exclusive lock.
A killed running coordinator is blocked, never reported recovered by editing
state.json. Recovery from a running state requires a new task after audit.
